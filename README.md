# mikeryan

**タイムラインもプロフィールも、ひとつのGitHub Pagesで。**

mynostr / mynostr_profile を統合した、テキスト中心のNostrクライアントです。
画面はTwitterに近い3カラム、丸いアバター、青いアクション、投稿ごとの返信・いいね・共有で構成しています。
スマートフォンでは下部ナビゲーションに切り替わります。ライト／ダーク／システム設定に対応します。

アプリ本体はHTML・CSS・JavaScriptのみです。サーバー、npm install、外部CDN、APIキーは不要です。
コード、画面、これから署名するイベントの `client` タグは **mikeryan** です。過去の他クライアントの署名済み投稿は改変しません。

## まず動かす

ZIP内の `mikeryan/` の**中身**をGitHubリポジトリのルートに置きます。`index.html` がリポジトリ直下にある状態にしてください。

最も簡単な公開方法は、GitHubリポジトリの **Settings → Pages → Deploy from a branch → main / (root)** です。
アプリの公開元を `/docs` にしないでください。`docs/` は利用説明だけです。
公開URLは通常 `https://<owner>.github.io/mikeryan/` です。リポジトリ名が異なっても相対パスで動きます。

テストしてから公開する方式も同梱しています。PagesのSourceで **GitHub Actions** を選択すると、
`.github/workflows/pages.yml` が構文確認、単体テスト、静的ファイルの構成を実行し、`dist/` だけを公開します。
この方式ではテスト用署名コード・fixture・開発スクリプトを公開物に含めません。
両方の方式を同時に有効化する必要はありません。ブランチ名が `main` 以外ならworkflowを変更してください。

ローカル確認は以下です。`file://` で直接開く方法は使用しません。

```sh
cd mikeryan
python3 -m http.server 8080
# http://localhost:8080/ を開く
```

開発用コマンドはNode.js 20以上で実行できます。依存パッケージのインストールはありません。

```sh
npm run check
npm test
npm run build
```

## 使える機能

| 分野 | 内容 |
| --- | --- |
| タイムライン | グローバル、フォロー＋自分のホーム、最新・新着・過去の取得、重複除去 |
| 投稿 | テキスト投稿、返信、スレッド、いいね、URL / nostr:note のコピー、下書き保存 |
| 通知 | 自分宛ての投稿・返信・リアクション |
| プロフィール | 表示名、名前、画像、カバー、自己紹介、NIP-05、Webサイト、Lightning Address、hex / npub コピー |
| 編集 | NIP-07で自分のプロフィールを編集。未知の既存フィールドも保持 |
| ユーザー一覧 | 投稿、フォロー、フォロワー、公開ミュート、公開リレーの5タブ |
| フォロー | 一覧上でフォロー／解除。ページ遷移なし。相互フォロー表示も更新 |
| リレー一覧 | NIP-65 kind:10002、旧kind:3のリレー情報にも対応 |
| 認証マーク | 投稿・通知・プロフィール・ユーザー一覧で同じNIP-05検証結果を利用 |
| 検索 | hex / npub / nprofile / NIP-05、note / neventから該当画面へ。小画面はヘッダーの検索ボタン |
| 設定 | リレー、読み取り台数、取得間隔、件数、名前／本文／公開鍵ミュート、JSON入出力、テーマ |
| 運用 | 通信量・REQ数・休止理由の表示、未完了送信の手動再送、明示操作によるリレーAUTH |

フォロワーは**設定した読み取りリレーで確認できた範囲**です。全Nostrの正確な総数とは表示しません。
公開ミュートの一覧はkind:10000の公開pタグのみで、暗号化された非公開部分は復号しません。
DM、Zap支払い、画像アップロード、リポスト作成など、元プロジェクトにない機能は追加していません。

## ログインを繰り返さない

NIP-07対応の署名拡張機能を有効にし、一度「NIP-07でログイン」を押します。
保存するのは公開鍵だけです。次回起動はその公開鍵で画面を復元し、ログインボタンを再度押す必要はありません。
復元後、最初の書き込みで拡張機能の公開鍵との一致を確認します。異なる場合は署名を止め、設定から切り替えるよう案内します。

**拡張機能が出す署名許可の確認は別です。** アプリは許可ダイアログを迂回しません。
秘密鍵の入力欄、nsecの保存、秘密鍵のエクスポートは実装していません。
ログアウトすると公開鍵の自動復元を止めます。設定・公開キャッシュ・下書きは別に残ります。
共有端末では、必要に応じてブラウザーのサイトデータも削除してください。

## 通信の設計

「表示する機能は残し、同じデータを取り直さない」を中心にしています。

- 一つの通信層を全画面で共有。SharedWorker対応環境では同じアプリの複数タブ間でも接続を共有します。
  非対応・起動失敗時はタブ内共有へ切り替えます。
- 1リレー1接続、1リレー1件ずつの有限取得。EOSEまたはタイムアウトで必ずCLOSEし、定期ポーリングはしません。
  接続自体は短時間再利用し、通信待ちがなければ2分で閉じます。
- リレー別キュー、既定1.2秒間隔、同じ問い合わせの実行中統合、短期問い合わせキャッシュ。
- 投稿ID、取得ページ、プロフィール、リスト、NIP-05を保存。画面に戻ると保存済みの内容を先に使います。
- プロフィール取得は80msまとめてから、著者ごとのlimit:1フィルターを最大20個ずつ送ります。
  投稿が多い一人のユーザーに取得枠を占有させません。
- フォロワー・ミュート・リレーは開いたタブだけ取得。返信元の未取得プレビューはクリックしたときだけ読みます。
- NIP-05は画面付近の名前だけ検証。同時HTTP取得は2件まで。同じ識別子や応答に含まれた他の有効な名前も再利用します。
- rate-limited / blocked / AUTH要求 / 接続失敗では休止期間を保存します。自動再接続ループや無限再送は行いません。
- 投稿は設定した各リレーへ1回ずつ送信し、OK応答で受理を確認します。未達は署名済みイベントのまま保存し、利用者が再送します。
  ACK済みのリレーには同じイベントを送り直しません。

| キャッシュ | 標準期間 |
| --- | --- |
| kind:0プロフィール | 6時間 |
| フォロー・公開ミュート・公開リレー | 5分 |
| 正常に取得を終えたが見つからなかったデータ | 10分 |
| 同一問い合わせ | 30秒 |
| 正常に取得したNIP-05の公開鍵対応 | 24時間 |
| NIP-05の通信失敗・未登録 | 15分 |
| 投稿・取得ページ・署名済み未完了送信 | 7日を基準 |

保存済みページは新着を自動取得しません。更新には「新着を確認」「最新」「プロフィール更新」「一覧を更新」を使います。
キャッシュ削除は再取得を増やすので、通常は不要です。キャッシュは定期的なローカル整理で約6,000レコードを目安に抑えます。
期間は各レコードの更新時点を基準とし、表示済みページは再利用する場合があります。恒久アーカイブではありません。

読み取り台数を1台にすれば通信はさらに減りますが、見つかる投稿や可用性もそのリレーに依存します。
既定の2台は元のmynostr設定を引き継いでいます。新しい追加リレーへ勝手に接続する探索は行いません。

**ブロックされない保証はできません。** リレーごとの利用条件、認証、料金、IP制限、保存範囲はクライアントから制御できません。
無駄な通信と再試行を抑える設計であり、制限の回避やIPのローテーションは実装していません。

## 元の表示条件に注意

`default.json` は添付mynostrの設定を残しています。初期状態では、本文に `https`、`nostr:`、`#` がある投稿、
かながない投稿、`name` / `display_name` が揃わない投稿者などがタイムラインで非表示になります。
**「取得に失敗した」のではなく「元の条件で隠れている」場合があります。**

広く表示するには、設定の **「表示フィルターをすべて解除」→「設定を保存」** を操作してください。
これはローカル表示条件の解除であり、アカウントの公開ミュートリストをリレー上で書き換える操作ではありません。
明示して開いた個人プロフィールの投稿タブは、元mynostr_profileと同様、タイムラインの表示ミュートとは別にその人の投稿を表示します。

## 旧設定の移行

同じオリジンに旧サイトのlocalStorageが残っていれば、初回にリレー・件数・ミュート・保存済み公開鍵を移行します。
旧2アプリに別々のリレー設定がある場合は重複を除いて統合します。旧保存項目は削除しません。
現在の設定はアプリの配置パス別に名前空間を分けます。違うオリジンや別ブラウザーへは、JSONエクスポート／インポートで表示設定を移します。
公開鍵は別に一度ログインし直します。JSONに秘密鍵は入りません。

同じ配置先では旧 `?hex=...`、`?npub=...`、`?view=me`、`?settings=1`、スレッドのクエリー形式も解釈します。
新しいリンクは `#/profile/<hex>/posts`、`#/thread/<id>` です。
**削除した別リポジトリの古いURLを、新リポジトリから自動転送することはできません。** 必要なら旧サイト側に転送を設置してください。

## 安全性と検証範囲

受信イベントはIDとBIP-340署名を検証してからキャッシュ・表示します。
署名検証とNIP-19は同梱コードで、外部CDN依存はありません。署名の作成はNIP-07に限定しています。
この同梱検証器は第三者のセキュリティ監査済みという意味ではありません。詳しくは `docs/SECURITY.md` を参照してください。

NIP-05の青マークは、識別子のHTTP応答と投稿者公開鍵の一致を表します。
実在する本人や発言内容の正しさの保証ではありません。通信・CORSで検証できない場合は `?`、不一致・未登録は `!` で区別します。

同梱テスト結果: **52件のNode単体テストと24件のオフラインChromium画面テストを通過**。
画面テストはURLアクセスが制限された環境のため、通信・保存・画面遷移・SHA-256にテスト用アダプターを使用しました。
実際の公開リレー、実NIP-07拡張機能、GitHub Pages公開、実ブラウザーのSharedWorker／IndexedDB連携はこの環境では未検証です。
実通信を含めて再確認するための `tests/browser_smoke.py` もあります。実施内容は `docs/TESTING.md` と `docs/TEST_RESULTS.md` に記録しています。
