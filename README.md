# mikeryan 1.1.1

`mynostr` と `mynostr_profile` を一つの静的サイトに統合した Nostr クライアントです。GitHub Pages 一つで動きます。アプリの実行にバックエンド、外部 JavaScript CDN、npm install は不要です。

## 投稿の読み込み

| ボタン | 基準と動作 |
| --- | --- |
| 下に読み込む | 画面内の一番下の投稿を基準に、古い側へ最大30件。 |
| 上に読み込む | 画面内の一番上の投稿を基準に、新しい側の近い投稿を最大30件。現在位置を飛ばして最新30件を取る操作ではありません。 |
| 最新を読み込む | 押した時点の現在時刻から古い側へ最大30件。タイムラインを置き換えて先頭へ移動します。 |

3ボタンはヘッダーの直下でスクロールに追従します。ホーム、グローバル、通知、プロフィールの投稿、スレッドの返信で同じ操作を使います。上・下への追加では読んでいる投稿の画面上の位置を維持します。読み込み中は重複操作を受け付けません。

「現在位置」は読み込み済み全体の最古・最新の投稿ではなく、実際に画面に見えている投稿で決めます。すでに表示されている範囲を指定すると、その範囲もリレーから再取得します。投稿IDで二重表示を防ぎますが、古い取得結果を代わりに返しません。

30件は一度に反映する投稿の上限です。ミュート条件によって表示数は減ります。表示数を30件にするための自動追加取得はしません。非表示だけのページでも同じ期間を繰り返さないよう、次回の手動操作用の位置だけを記録します。

### プロトコル上の境界

NIP-01 の時刻は秒単位で `since` / `until` の両端を含みます。また `limit` 付き応答は新しい順です。このため境界の同じ秒に複数投稿がある場合、最大30件を飛ばさず選ぶための追加受信が必要です。通常の下方向は基準の投稿を含めて31件程度、病的な同秒集中ではフィルター当たり最大1600件までに制限します。複数リレー・複数フィルターの応答は重複排除して最大30件を反映します。

上方向は狭い期間から検索し、必要に応じて期間を調整します。1回のクリックで最大6回の期間問い合わせに制限します。近い範囲を確定できなければ警告し、続きは同じボタンで手動取得します。追加受信が発生するので「通信するイベント総数が必ず30以下」とは保証しません。リレーの独自上限や欠落により、全履歴が取得できる保証もありません。

## 永続キャッシュを使わない通信設計

投稿本文、ページ、いいね、問い合わせ結果、NIP-05検証結果は永続保存しません。本文とページ内の自分のいいねは、手動読み込みのたびに対象を絞って再取得します。IndexedDB、Service Worker、取得結果のTTLキャッシュはありません。

**1.1.1では、正常に取得できたプロフィールだけをタブ内のメモリで再利用します。** 同じ人が次の30件に登場しても、kind 0を再要求しません。画面を切り替えても保持し、ページの再読み込み、タブを閉じる、ログアウト・アカウント切り替えで消えます。既知プロフィールの目録は最大2000人です。これは一時的なメモリ保持であり、ディスクの保存キャッシュではありません。

プロフィールを最新にしたい場合は、その人の「プロフィール更新」を押します。プロフィール保存・フォロー変更前の確認はメモリを使わず、全設定リレーから最新データを確認します。読み取りリレーの構成が変わった場合も、新しい構成で確認します。未取得・不正なプロフィールや不完全な通信結果を、取得成功として再利用しません。

通常の1ページ取得は以下の流れです。

1. 時間・投稿者・kind・件数を指定して最大30件を選びます。
2. 未知の投稿者を `kinds:[0], authors:[...], limit:人数` のフィルタにまとめ、そのページの投稿IDに限定した自分のkind 7フィルタと同じREQで取得します。プロフィールだけを求める他機能の同時要求も共通キューへまとめます。
3. 各リレーのEOSE後にCLOSEします。完了済みのページ結果は使い回さず、接続と処理中の同一要求だけを共有します。

リレーがプロフィールの件数を独自制限したり旧版を混ぜたりして、一部の投稿者しか返さない場合があります。このときは**そのリレーで不足した人だけ**を1人1フィルタ・limit 1で一度補完します。20フィルタずつに区切り、取得済みの人やいいねを補完要求に含めません。空のEOSEには補完せず、拒否・タイムアウト・レート制限後には自動再試行しません。全リレーでの完全性・最新性を保証する仕組みではありません。

定期ポーリング、スクロールによる投稿取得、無制限の再接続はありません。要求間隔、接続共有、レート制限時の休止は維持しています。

### 1.1.0との計測比較

同一の署名済みテストイベント、2リレー、ログイン済みの5回の手動読み込みを、変更前後の実装と模擬リレーで比較しました。REQは合計30回→20回、送信JSONバイトは48.12%減、受信JSONバイトは24.82%減でした。サーバーのCPU負荷、TCP/TLS、NIP-05、画像、ログイン時の初期取得は含みません。元のmynostrの実環境ベンチマークではありません。

30人の未知プロフィールがすべて見つかる通常のログイン済みページでは、1リレー当たり投稿1REQ＋プロフィール/いいね1REQの計2REQです。「上に読み込む」の期間探索、同秒境界、100人を超える投稿者条件、プロフィール欠落・件数制限時には増えます。必ず2REQ以下になる保証ではありません。

NIP-05のHTTP検証と画像は表示に伴って別途通信し、設定で無効にできます。NIP-05の結果再利用は追加していません。設定されたリレーの利用規約・有料条件・レート制限による拒否を回避する機能ではありません。

詳細と再現コマンドは [通信計測](docs/TRAFFIC.md) を参照してください。

### 保存するユーザー操作情報

ログイン公開鍵、設定、下書きは localStorage に保持します。秘密鍵は保存しません。自分が署名した未完了の送信と、拒否されたリレーへの再試行抑制情報も保持します。これらは取得結果のキャッシュではありません。未完了の送信は設定から未達リレーにだけ再送できます。

静的なHTML・JS・CSS・画像のHTTPキャッシュはブラウザーの機能です。アプリの取得データキャッシュとは別です。今回、JSの全依存モジュールとCSSに `?v=1.1.1` を付け、旧モジュールが混ざる更新事故を抑えています。

## その他の機能

NIP-07拡張機能によるログインと投稿・返信・いいね、プロフィール編集、フォロー・フォロワー・相互フォロー、公開ミュート、NIP-65リレー一覧、NIP-05識別子と公開鍵の一致検証、公開鍵・投稿ID検索、設定のJSON入出力を含みます。プロフィールとタイムラインは同じサイト内で移動します。

一度ログインした公開鍵は次回も復元されます。書き込みには拡張機能による署名が必要です。拡張機能自体の承認ダイアログを迂回しません。新しく作成するイベントのクライアントタグは `mikeryan` です。

## 配置と更新

ZIP内の `mikeryan/` の中身をリポジトリ直下に置きます。`index.html` が直下にある状態です。GitHub Pages の公開元はブランチのルート `(root)` を選びます。`docs/` は説明ページで、アプリの公開元ではありません。

既存プロジェクトの更新は同じ位置に上書きして再公開します。独自に変更した `default.json` は残してください。ログインや設定のためにサイトデータを消す必要はありません。HTMLまで古い場合は更新後に Ctrl+Shift+R で読み直してください。

1.0系のIndexedDBはこの版では読み書きせず、削除もしません。以前の版の「未完了の送信」が残っている場合は更新前に処理してください。詳細は [移行](docs/MIGRATION.md) にあります。

ローカル確認:

```sh
cd mikeryan
python3 -m http.server 8000
# ブラウザーで http://localhost:8000/ を開く
```

Node.jsがあれば次でソース確認・単体テスト・公開用コピーを作成できます。

```sh
npm run check
npm test
npm run build
```

`dist/` は静的な公開ファイルだけです。同梱の `.github/workflows/pages.yml` を使う場合は GitHub Pages のソースを GitHub Actions に設定します。

```text

js/core/       設定定数、イベント検証、画面・セッションのデータ、ルーティング
js/network/    リレー接続・キュー・同時要求の統合・プロフィールの一括取得
js/feed/       上・下・最新の読み込み、表示条件
js/profiles/   プロフィール・編集・NIP-05検証
js/social/     フォロー・いいね・送信
js/settings/   設定の入出力・画面
js/ui/         投稿・ユーザー名・共通DOM
assets/css/    レイアウトと部品
```
