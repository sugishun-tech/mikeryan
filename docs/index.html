舞久雷庵 1.3.5

手動で読み込む

アクセスやスクロールだけでは投稿・公開リストを取得しません。「下」「上」「最新」で最大30件を取得します。上下は実際に見えている投稿が基準です。3ボタンはスクロールに追従します。フォロー・フォロワー・ミュート・リレーも各取得ボタンで読み込みます。

プロフィールの保存と更新

取得したユーザー情報ではプロフィールを永続保存します。取得済みの人は投稿・通知・各一覧・プロフィールページで同じ保存データを使い、再読み込みやログアウト後も再利用します。新しい内容が必要な場合はその人の「プロフィールを更新」を押します。未知の人のページへ移動しただけでは取得しません。

NIP-05の結果も保存時点の情報を使います。認証マークには検証日時を表示します。プロフィール更新で再検証します。プロフィール画像はURLを保存し、画像ファイル本体を保存する機能はありません。

公開リレーを編集する

自分のプロフィールのリレータブでは、取得した公開リレーの削除と、URL・用途を指定した追加ができます。変更時は最新の情報を取得し、署名して公開します。設定ページの接続先リレーは変更しません。他人の公開リレーは編集できません。

設定と保存

投稿・フォロー・フォロワー・ミュート・公開リレー・一般の問い合わせ結果はキャッシュしません。通知から返したいいねは、重複送信を防ぐため送信記録と対象リアクションを保存します。接続先設定、ログイン公開鍵、下書き、未完了送信、リレー休止情報は従来どおり保存します。秘密鍵はNIP-07拡張機能が扱い、アプリへ保存しません。

初期状態は元の強い表示条件を引き継ぎます。既存の表示条件は自動変更しません。取得の未完了メッセージがある場合は、まず同じ取得ボタンで再試行してください。保存に失敗した旨が表示された場合は、サイトデータの保存許可と容量を確認してください。

取得が未完了の場合

リレーの部分応答で一覧や現在位置を飛ばさず、再試行できる状態を保ちます。フォローと公開ミュートでは名前や相互状態の失敗でユーザー行を省きません。フォロワーはリレー別の検索と本人のフォロー先への直接照会を併用します。空・古い応答で受信済みのフォロー証拠を消しません。最新状態の確認ができなかった場合は警告を表示し、「未確認の候補を再確認」で再試行します。相互関係の証拠がない場合は「相互未確認」と区別します。選択したリレー以外のデータを自動取得するものではありません。

画面と表示名

アプリの表示名は「舞久雷庵」です。右側の検索バーは削除しました。モバイル画面のヘッダーにある検索ボタンは引き続き使えます。既存の設定・ログイン・下書き・プロフィールを引き継ぐため、内部の保存キーは維持しています。

投稿の埋め込み

NIP-21のnote・nevent・npub・nprofile・naddr、HTTPS画像とNIP-92、YouTubeのwatch・短縮URL・shortsを表示できます。kind:6・16のリポストはリポスト者と元の投稿、qタグは引用として表示します。

各投稿から直接展開する埋め込みは全種類合計で1枠、入れ子は最大2段です。本文で最初の対応候補を表示し、Nostr参照は最初のURIだけが候補になります。本文候補がなければ最初のq引用を使います。元投稿を深さ0として1段目・2段目まで展開し、3段目は通常リンクにします。リポストの元投稿も1段として数えます。失敗時はリンクを残します。同じ画像や動画が別の投稿に含まれていても、それぞれ表示します。初期設定のhttps / nostrミュートも維持しているため、該当投稿を表示する場合は設定でそのパターンを削除してください。

X/Twitterのリンク

Xの投稿URLは公式iframeで表示します。一投稿1枠・最大深度2に従い、同じURLを含む別投稿でも表示します。本文の通常リンクは残します。

いいね通知と操作

通知に届いたいいね・リアクションには、ハートを押していいねを返せます。送信済みのハートは赤くなります。通常の投稿・返信・リポストにはいいねできません。送信結果が未確認の場合は設定の「未完了の送信」から再送します。操作名を「下」「上」「最新」「ポスト」に短縮し、投稿の「リンクをコピー」を削除しました。
