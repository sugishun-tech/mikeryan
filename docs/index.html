mynostrとmynostr_profileを一つに統合。表示したデータは再利用し、新着は必要なときに確認する、テキスト中心のNostrクライアントです。

はじめる通信認証マーク表示条件開発・検証

タイムラインと通知

グローバル、フォロー中のホーム、通知、返信とスレッド。Twitterに近いレイアウトで、ライトとダークを切り替えられます。

プロフィール

編集、フォロー、フォロワー、相互表示、公開ミュート、リレー。別サイトへの移動も、画面ごとの再ログインも不要です。

はじめる

署名拡張機能を有効にし、「NIP-07でログイン」を一度押してください。次回からは保存した公開鍵で画面を復元します。秘密鍵をこのサイトに入力する必要はありません。署名を許可する拡張機能側の確認は引き続き必要になる場合があります。

右上の検索欄でnpub、hex、NIP-05を指定できます。小画面ではヘッダーの検索ボタンを使います。投稿IDやnostr:noteも指定できます。

投稿は署名後にリレーのOK応答を確認します。一部または全部が失敗した場合は、設定の「未完了の送信」から同じ署名済みイベントを再送できます。送信済みのリレーには同じイベントを重ねて送りません。

新着を勝手に取り続けない

新着確認は手動です。取得を終えた購読はCLOSEし、画面に戻ると保存済みページを使います。対応ブラウザーではSharedWorkerでタブ間の接続も共有し、非対応環境では各タブ内で共有します。利用中の方式とREQ数は設定の通信状況に表示します。

保存対象標準期間
プロフィール6時間
フォロー・公開ミュート・公開リレー5分
同じ問い合わせ30秒
NIP-05の公開鍵対応24時間
投稿・ページ・未完了送信7日を基準

初期値は読み取り2リレー、要求間隔1.2秒です。1リレーにすると通信はさらに減りますが、見つかる投稿もそのリレーの範囲に限られます。フォロワー一覧も全Nostrの総数ではありません。

リレーの料金・認証・IP制限などはサービス側の条件です。この設計は無駄な通信を抑えるもので、ブロックされないことや履歴の完全取得を保証するものではありません。

青いチェックは何を示す？

投稿者が指定したNIP-05の公開鍵と、実際の投稿者公開鍵が一致したことを示します。実在する人物の本人確認や発言内容の保証ではありません。不一致・未登録は「!」、通信などで確認できない場合は「?」です。名前にあるマークにカーソルを合わせると理由を確認できます。

同じ名前の繰り返し表示で同じ検証をし直しません。画面付近の名前だけを確認し、HTTP同時取得数も2件に抑えています。画像とNIP-05の外部アクセスは設定で無効化できます。

投稿が少ないときは表示条件を確認

元mynostrの初期条件を引き継いでいるため、URL・nostr:・#・かなを含まない投稿や、名前情報が揃わない投稿者がタイムラインで非表示になる場合があります。

設定 →「表示フィルターをすべて解除」→「設定を保存」でローカル条件を解除できます。これは公開ミュートリストそのものを変更する操作ではありません。明示して開いた個人プロフィールの投稿は、タイムライン条件とは別に表示します。

同じオリジンに旧設定が残っていれば、初回に旧2アプリのリレー・ミュート・公開鍵を取り込みます。別オリジンへはJSON入出力で設定を移し、ログインを一度行います。

一つのGitHub Pagesで公開

リポジトリ直下にindex.htmlを置き、Settings → Pagesでmain / (root)を公開します。ここにあるdocsフォルダーは利用説明用で、アプリの公開元には指定しません。GitHub ActionsをSourceに選ぶテスト付き公開ワークフローも同梱しています。

python3 -m http.server 8080
# 開発確認は http://localhost:8080/

npm run check
npm test
npm run build

ブラウザーで実行するアプリには、npmパッケージ、外部CDN、バックエンドは不要です。署名はNIP-07へ委譲します。機能別にauth、network、feed、profiles、social、settings、uiを分離しています。
